# 测试指南

> 本文定义本项目的测试分层、手动回归矩阵和发布前检查项。
> 测试报告使用 [测试报告模板](../history-version/templates/test-report.md)。

## 1. 测试原则

- 本项目是 Windows GUI 工具，核心行为依赖真实键盘事件，暂无可替代的自动化 GUI 测试。
- 每次代码变更至少完成“导入检查 + 受影响的手动用例”。
- 涉及 `engine/` 的改动必须额外运行 `test_sendinput.py` 做隔离验证。
- 发布前必须完成完整回归矩阵和打包验证。
- 测试结论只记录实际执行过的项目；未执行的要标注“未验证”。

## 2. 测试分层

| 层级 | 目的 | 入口 |
|---|---|---|
| 导入检查 | 确认模块路径和新目录结构可正常加载 | `python -c "import main"` |
| SendInput 隔离测试 | 排除 GUI 干扰，验证底层按键发送 | `test_sendinput.py` |
| 功能手动测试 | 验证文本输入、控制、字符兼容和缩进 | 启动应用 + 记事本 / PTA |
| 打包验证 | 确认 exe 在目标环境可运行 | `pyinstaller build.spec` + 运行 `dist/自动打字.exe` |

## 5. 重点回归说明

### 5.1 换行与自动补全

- `\r` 必须跳过，否则会产生双空行并干扰行首状态。
- 每个 `\n` 后额外等待 `0.05s`，给编辑器处理换行和自动缩进。
- 在 PTA / VS Code 等有自动补全的编辑器中，确认闭合括号没有被重复插入。
- 测试 `@Override`、注解、连续空行等容易发生粘连的场景。

### 5.2 缩进策略

- `skip_indent=True`：引擎跳过每行开头的空格和 Tab，由目标编辑器自动缩进。
- `skip_indent=False`：保留原文缩进，适用于记事本等没有自动缩进的编辑器。
- 同一段代码分别在 PTA 和记事本中验证，确认两种策略都符合预期。

### 5.3 字符通道

- ASCII 字符必须优先使用扫描码模式。
- 中文、emoji 等无法映射到键盘布局的字符自动回退到 Unicode 模式。
- 若某个字符异常，先用 `test_sendinput.py` 判断是映射问题、时序问题还是目标应用兼容问题。

## 8. 已知限制

- 不同编辑器对按键时序和自动补全的处理不同，无法保证所有第三方应用行为一致。
- 打字速度过快可能触发平台风控；建议保持在 100ms–300ms。
- 本项目不修改目标应用，目标窗口必须保持前台激活。
